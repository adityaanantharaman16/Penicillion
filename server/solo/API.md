# Daily Rounds, Practice and Archive

The guest or signed-in session determines the player on every route. The HTTP service supplies the complete-request receipt time and rejects foreign origins, unauthorized session changes and oversized bodies. The service accepts epoch milliseconds internally; its HTTP routes have no clock override. All dates below are New York civil dates. Render reset and grace timestamps in the visitor's time zone.

| Method and path | Input | Response |
|---|---|---|
| GET /api/daily | — | Current issue, server time, a resumable ranked run ID and phase, and any overnight run still within its grace period. |
| POST /api/runs | mode, commandId; archive also requires a past date; practice accepts untimed | Start or resume a ranked daily, or allocate an unranked seven-slot run. |
| GET /api/runs/:id | — | Private snapshot. Materializes any elapsed deadline before returning. |
| POST /api/runs/:id/answer | roundId, answer, commandId | A locked reveal, feedback on the same clock, or a spelling suggestion. Confirm the suggested display term with a new answer command. |
| POST /api/runs/:id/skip | roundId, commandId | A zero-point reveal. |
| POST /api/runs/:id/next | roundId, commandId | Opens the following prompt and deadline, or shows the specimen log after the seventh reveal. |
| GET /api/distribution?date=YYYY-MM-DD | Optional date defaults to today | Finishers-only distribution, sample size, update time and the player's score. |
| GET /api/history?before=cursor | Optional exclusive cursor from the previous page | Most recent 36 private runs and the current collection and streak. |
| GET /api/archive?before=YYYY-MM-DD | Optional exclusive date | Up to 36 published past issues, newest first. |
| GET /api/archive/:date/explorer | Past date | Annotations and sources per accepted answer. An answer list is withheld if this visitor has already opened that category in an unfinished, unexpired ranked issue. |
| POST /api/runs/:id/report | slot (1–7), text (1–280 characters), optional commandId | Private report acknowledged for editorial review. Five per identity per rolling 24 hours, with a Retry-After header on rate limit. |

Use new opaque command IDs (8–96 letters, digits, underscores or hyphens) for new actions. A network retry repeats the exact original body and ID. Commands restrict allowed keys, reject client scores, and require the current round ID. A stale request returns 409. An account or guest cannot read another player's run. A missing or inaccessible run returns 404. Refresh after a conflict. Reports should include a command ID to survive a lost acknowledgment.

A snapshot carries id, mode, date, issue, ranked, untimed, contentRelease, scoringRelease, phase, take, takes, roundId, deadline, serverNow, prompt, topic, scope, total, max, results and nextResetAt. Each revealed row has its slot, prompt, status, canonical term, tier, points, fact, reason and source. Only a completed specimen log includes bestFind, alternatives, stats and the eligible daily distribution. Alternatives can be absent in a one-answer category or when the active-issue privacy rule applies.

**Timing and scoring.** An issue has seven fixed prompt revisions and scoring release, with one ranked allocation per identity. The effective deadline is the earlier of 25 seconds after opening and the overnight grace cutoff. Receipt at the deadline earns zero. A background tab, refresh or miss cannot extend the clock. A reveal waits indefinitely within the daily grace period. At ten minutes past midnight Eastern, an unfinished old issue expires without rank credit. The seventh outcome finalizes the run before acknowledgment, so a reader can finish viewing its reveal after grace. The following day's allocation is independent. During overnight grace, a player with a still-rankable run cannot replay that dated archive or open its explorer until the run finishes or grace ends. Other players retain after-reset access. Practice supports an untimed clock, and the archive is always unranked.

**Durability.** A transaction locks the principal, serializes its run, settles any expired deadline, verifies the round ID, and commits the outcome, total and idempotency receipt together. An exact retry receives the original result. Recap retries also enforce current spoiler permissions before returning optional alternatives. A different payload signed under the same previously recorded key receives 409. Rejected gameplay text is represented only in a keyed command signature. Raw text is retained solely for an explicit private report, readable by editors with database access. Actor locks precede run locks and cache invalidation. Account claims lock both principals in a stable order in the identity transaction. On a collision the account's ranked allocation survives and its imported guest run becomes unranked history. Ranked runs from an excluded guest also become private unranked history, even when the receiving account has no collision. The preview reports the total number of ranked records that will enter private history.

**Content.** Seed writes a draft and all its source, tier, prompt, canonical mapping and normalization records, then publishes in one transaction. A digest prevents replacing a release under the same identifier. Published mappings and dated sets are immutable. Composite foreign keys connect every outcome to the exact run, prompt revision and assigned points. The database keeps aliases local to each prompt. Explicit scope exclusions and ambiguity take precedence and are never converted into suggestions. Unknown long terms can receive a single-edit suggestion after a capped indexed candidate search. A known term in another category, a changed directional or clinical qualifier, short text or ambiguous alternatives suppress a suggestion. Only the player's confirmed exact alias scores.

**Schedule and availability.** After migration, `npm run seed` imports the editorial release and adds any missing issues from seven days ago through 35 days ahead. Repeat the same command daily in the deployment's scheduled job. A transaction lock makes concurrent refill safe. Existing sets never change. The wheel has at least 56 daily categories and prevents repeats across the seven intervening issues. At a release boundary, fill only from eligible categories absent from the adjacent seven issues on each side. The release must retain at least seven open practice prompts and at least two relay categories with eight or more canonical answers. If inventory cannot meet these requirements, the refill rolls back, the already-issued dates retain their exact sets, and operators restore the last valid release file and repeat the job. A missing current issue returns 503. The request handler never invents a new daily. Practice selects seven unseen then least-recently-opened prompts from the open pool, excluding any reserved current or future prompt. Relay reads only sufficiently large, unreserved open categories and pins the prompt's release identity in the room.

**Results.** Eligible completed ranked totals feed the histogram. The payload withholds bins and percentile below 20 eligible finishers. Otherwise, each bin is a real count and includes a range for the viewer's score. Competition rank equals one plus the number of strictly higher eligible scores. The displayed percentage is strictly lower divided by all eligible finishers, including self and ties, rounded down to one decimal. Counters are rebuilt from indexed PostgreSQL rows when a match finalizes, a claim changes ranking, an account is excluded or a run is deleted. A missing histogram row is rebuilt on the next read or invalidation. A completed but excluded identity can see the genuine distribution without a personal rank or percentile. The editorial query view `solo_observed_frequency` counts eligible completed answers by release, prompt and canonical concept. Its counts have no effect on today's price. Three-, seven- and fourteen-day streaks unlock permanent cosmetic collection entries. Missing an Eastern issue resets the active streak. An eligible finish yesterday keeps a streak alive until today's issue closes.

**Verification.** With local PostgreSQL running, execute `node --test server/solo/test/postgres.test.mjs`. This creates and removes an isolated schema. Two connection pools race starts and duplicate commands, exercise expiry, replay a claim collision, validate cache invalidation and test both DST transitions. Synthetic score distributions never enter the live game.

Editors run `node server/solo/reports.mjs list` with their private database role to read the 50 oldest open reports. The output names the field `untrusted_player_text` and omits the reporter's identity. Verify scope and sources independently, author changes in an unpublished release, and publish through the regular import. After publication, `node server/solo/reports.mjs resolve REPORT_ID added PUBLISHED_RELEASE_ID` links the review to the release. For an out-of-scope suggestion use `resolve REPORT_ID no-change`. This tool records editorial disposition and never changes a run or an answer mapping.

Tier labels in reveals, alternatives, recap, archives and shared results use the current public vocabulary in `web/rarity.js`, derived from the stored points. Archived editorial content, score assignments and prior results retain their published revisions. Relay pass events carry the awarded `points` and public `tier` when known.
