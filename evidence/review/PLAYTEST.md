# Independent integrated playtest

**Night Culture, 12 November 2026.** An independent agent played the running application in Chrome 157.0.8103.78 using separate guest profiles and the local identity provider’s Violet Moss and Rowan Reed accounts. The desktop viewport was 1440 × 900. The primary phone viewport was 360 × 740 with touch and reduced-motion emulation. The final two-profile smoke used the player’s port 4320 and locally seeded edition `night-culture.2026-11.f275d05c0e60`. Both final Chrome guests played unranked practice and a private relay. Additional WebKit 26.5 and Firefox 151.0 guests each earned 100 points in practice, opened the sourced fact, advanced to the next prompt and passed a slide across browser engines. ## Capacity evidence

I compared the raw 30-minute measurements with the report and ran independent read-only SQL against its completed database. Every plateau sample had 1,500 recently active solo identities and 500 connected relay seats, spread across 100 rooms. The two workers reached 320 successful gameplay writes per second. Server-side solo submission p95 was 28.9 ms and server event to non-sender peer p95 was 19 ms. The 500-seat reconnect storm recovered every connection. Two transport failures (“read ECONNRESET” and “socket hang up”) were recorded among 262,086 HTTP responses and socket commands, about 0.0008%. All 128 pre-deadline requests in the synchronized probe scored; all 32 post-deadline requests timed out.

My independent tally covered 113,734 stored outcomes. It found zero score-sum errors, completed runs with the wrong number of outcomes, duplicate ranked attempts, or repeated timeout events for a room/epoch. The benchmark’s separate audit found zero lost acknowledged outcomes. The long run used two native local workers, PostgreSQL 17.6, Redis 7.4.6, and a representative release with the same 1,565 mappings and scores as the final bank. The final revision removed two aliases. The benchmark host, client generator and data-service patch versions differ from a hosted deployment. [Independent audit](capacity-audit.json), [measured report](../load/CAPACITY.md), [environment comparison](../load/environment-2026-11-12T17-28-47-612Z.json)

The frozen build then ran two 90-second checks at the same 2,000-player load with the restricted game role on PostgreSQL 17.11 and Redis 7.4.12. The first short check’s relay p95 of 3,137 ms combined newly pushed events with the age of state received on reconnect. I verified the revised definition in the generator before the repeat. Established connections contribute only new, non-sender event deliveries. New connections contribute separately to dial-to-first-snapshot and first-event-age distributions. The repeat measured 8 ms p95 for 4,444 live deliveries and 19 ms p95 to first personalized state for 500 reconnects; its original mixed measure still read 3,004 ms. The frozen repeat recorded 11.9 ms solo p95, 166 peak writes/s, no unexpected failures and no late awards. I independently tallied 8,802 persisted outcomes from the first short run and 8,801 from the repeat, with zero score, finished-count, duplicate ranked, or double-timeout errors. The detached player installation also passed the WebKit/Firefox practice and relay check and the departed-seat receipt retest.
